
# Playwright BDD Automation Framework

A UI automation framework built with **Playwright**, **TypeScript**,
**playwright-bdd**, and the **Page Object Model (POM)**. It lets the
team write readable Gherkin feature files while running scenarios
through the Playwright Test runner.

## Overview

The framework separates test scenarios, step definitions, page
interactions, and execution configuration:

1.  **Feature files** describe scenarios in Gherkin.
2.  **Step definitions** connect Gherkin steps to TypeScript.
3.  **Page Objects** contain locators and reusable page actions.
4.  **`playwright-bdd`** generates Playwright tests from the feature
    files.
5.  **Playwright Test** executes the generated tests and produces
    reports.

## Technology Stack

-   Node.js
-   TypeScript
-   Playwright Test
-   `playwright-bdd`
-   Gherkin
-   Page Object Model (POM)
-   Optional: `dotenv` for environment variables

## Prerequisites

Install a supported Node.js LTS release and npm. From the project root,
install dependencies:

``` bash
npm install
```

If the required packages are not already installed:

``` bash
npm install -D @playwright/test playwright-bdd typescript
npm install dotenv
npx playwright install
```

Use package versions compatible with one another and preserve the
versions already used by the project unless an upgrade is intended.

## Installation

1.  Clone or copy the repository.
2.  Open a terminal at the project root.
3.  Install dependencies with `npm install`.
4.  Create a local `.env` file from `.env.example`, if the project uses
    one.
5.  Confirm `config/globalData.json` contains the correct environment
    URL.
6.  Install the Playwright browser binaries with
    `npx playwright install` if needed.

## Configuration

### Environment URL

Example `config/globalData.json`:

The Page Object uses this value to build the URL for the practice page.

### Environment variables

Example `.env.example`:

``` env
HEADLESS=false
ENV=QA
TAGS=@form
WORKERS=2
```

Copy `.env.example` to `.env` for local use. Keep passwords and other
secrets in `.env` or an approved secret store, never in
source-controlled JSON or code.

Environment variables only affect the framework if the relevant
scripts/configuration load and use them. If tag filtering is configured
through `playwright-bdd`, make sure the `TAGS` variable is available
when `bddgen` runs as well as when Playwright executes the generated
tests.

Keep selectors and reusable page interactions in Page Objects. Keep
scenario-specific assertions and orchestration in step definitions.

## Generate and Run Tests

Generate Playwright tests from the feature files:

``` bash
npx bddgen
```

Run the generated tests:

``` bash
npx playwright test
```

If these scripts exist in `package.json`, use:

``` bash
npm run bddgen
npm run test:bdd
```

The `bddgen` command generates tests; it does not run them by itself.
Run Playwright Test afterward.

To run a selected tag, set the environment variable using the syntax
appropriate for your terminal. In PowerShell:

``` powershell
$env:TAGS="@smoke"; npm run test:bdd
```

For a different tag:

``` powershell
$env:TAGS="@form"; npm run test:bdd
```

The `playwright.config.ts` BDD configuration must read the variable, for
example with the `tags` option supported by the installed
`playwright-bdd` version. Confirm the installed version's API if the
option is rejected. Ensure the variable is available during both
generation and test execution.

To clear a PowerShell environment variable in the current session:

``` powershell
Remove-Item Env:TAGS
```

## Headless and Headed Execution

A typical configuration reads the `HEADLESS` value from the environment:

``` typescript
const headless = process.env.HEADLESS !== 'false';
```

-   `HEADLESS=true`: run without showing the browser.
-   `HEADLESS=false`: show the browser.
-   If unset, the expression above defaults to headless mode.

Load `.env` before the configuration reads environment variables, and
ensure it is also loaded before `bddgen` if generation depends on those
variables. A tool such as `dotenv-cli` can load `.env` for each command.

## Authentication State

If a login setup creates `.auth/user.json`, Playwright can reuse it by
configuring:

``` typescript
use: {
  storageState: './.auth/user.json',
}
```

The state file must already exist and remain valid. Regenerate it when
the session expires. Do not commit `.auth/user.json` because it can
contain sensitive session information.

For public pages that do not require authentication, storage state may
not be necessary.

## Reports

A basic Playwright HTML reporter configuration is:

``` typescript
reporter: [
  ['list'],
  ['html', { open: 'never' }],
],
```

After running tests, open the HTML report with:

``` bash
npx playwright show-report
```

If Allure is installed and configured in the project, use the project's
configured Allure commands. Allure is optional and is not enabled by
this README alone.

## Team Contribution Guidelines

1.  Create or update a `.feature` file for each scenario.
2.  Add or reuse step definitions under `steps/`.
3.  Add page locators and reusable actions to the relevant Page Object
    under `pages/`.
4.  Avoid duplicating locators across step files.
5.  Use meaningful tags such as `@smoke`, `@regression`, and
    feature-specific tags.
6.  Do not edit files inside `features-gen/`; regenerate them with
    `npx bddgen`.
7.  Do not commit `.env`, passwords, `.auth/user.json`, test reports, or
    generated artifacts unless the repository policy explicitly requires
    them.
8.  Keep `package-lock.json` committed so team members install
    consistent dependency versions.
9.  Run the relevant tests locally before raising a pull request.
10. Coordinate changes to shared configuration files to reduce merge
    conflicts.

## Troubleshooting

### `bddgen` is not recognized

Install project dependencies and run:

``` bash
npm install
npx bddgen
```

### No tests are discovered

-   Check that the feature path in `playwright.config.ts` matches the
    actual folder.
-   Confirm the step definitions are included in `defineBddConfig`.
-   Run `npx bddgen` before `npx playwright test`.
-   Check whether the active tag filter excludes the scenarios.

### TypeScript cannot import `globalData.json`

Check that `tsconfig.json` includes:

``` json
{
  "compilerOptions": {
    "resolveJsonModule": true,
    "esModuleInterop": true
  }
}
```

Merge these options into the existing configuration rather than
replacing it blindly.

### Browser does not open

Check the `HEADLESS` environment variable and the value used in
`playwright.config.ts`. Also confirm the required browser binary is
installed:

``` bash
npx playwright install chromium
```

### Authentication state fails

Confirm `.auth/user.json` exists, was generated successfully, and has
not expired. Regenerate it using the project's authentication script if
necessary.
